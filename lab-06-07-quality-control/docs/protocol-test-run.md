## 1. Методика проверки

Проверка строится на последовательном выполнении сценариев:
1. подготовить тестового пользователя, баланс и позицию меню;
2. создать заказ через API;
3. инициировать оплату и зафиксировать идентификатор заказа;
4. проверить публикацию события `order_paid`;
5. проверить обработку события кухней и дальнейшее состояние заказа;
6. смоделировать недоступность RabbitMQ в контролируемой точке;
7. проверить сохранность состояния и возможность восстановления обработки;
8. выполнить регрессионные проверки идемпотентности и компенсации Saga.

Методика соответствует принципам документирования тестирования из ISO/IEC/IEEE 29119 и внутренним правилам команды. Номер редакции стандарта и внутреннего регламента в учебном примере не заявляется.

## 3. Результаты модельной проверки

Числа ниже — учебные значения, предназначенные для демонстрации формы протокола. Они не являются фактическими измерениями текущего стенда.

| Проверка | Критерий | Модельный результат | Оценка |
|---|---|---|---|
| Создание заказа | Заказ сохранён и возвращён идентификатор | Заказ создан | Соответствует |
| Публикация `order_paid` | Событие доступно обработчику | При отказе брокера событие не доставлено | Не соответствует |
| Обработка кухней | Worker получил событие и обработал его один раз | В сценарии отказа обработка не началась | Не соответствует |
| Повторная доставка | Повтор не вызывает повторного бизнес-эффекта | Требует отдельного подтверждения | Не проверено |
| Компенсация Saga | При отказе процесс завершается согласованной компенсацией | Данных модельного прогона недостаточно | Не проверено |

## 4. Заключение

В рамках учебного сценария подтверждается необходимость отдельной проверки надёжности публикации событий и повторной обработки сообщений. Сценарий отказа RabbitMQ является несоответствием модельному критерию, поэтому выпуск по этому протоколу не рекомендуется.

Заключение относится только к описанному сценарию и модельным условиям. Для фактического протокола необходимо приложить commit/hash сборки, версии инструментов, временные метки, логи, результат CI и подписи/согласование ответственных.

## 5. Приложения

- журнал HTTP-запросов с замаскированными секретами;
- фрагмент журнала API с correlation_id и order_id;
- сведения о публикации/доставке сообщения RabbitMQ;
- состояние заказа до и после проверки;
- отчёт регрессионного прогона CI.
