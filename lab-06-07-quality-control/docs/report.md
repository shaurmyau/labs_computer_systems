## 3. Дефекты

| ID | Дефект | Серьёзность / приоритет |
|---|---|---|
| BUG-001 | После фиксации состояния заказа событие `order_paid` может не попасть в RabbitMQ | Major / P1 |
| BUG-002 | Статус заказа обновляется с задержкой | Major / P2 |
| BUG-003 | Некорректное округление суммы при дробной скидке | Minor / P3 |

**Карточка BUG-001**

- **Условия:** PostgreSQL доступен, RabbitMQ становится недоступен во время публикации события.
- **Шаги:** создать заказ, оплатить его, остановить брокер, проверить состояние заказа и журналы.
- **Ожидается:** событие сохраняется для повторной отправки и после восстановления брокера обрабатывается один раз.
- **Модельный результат:** состояние операции сохранено, но событие не доставлено; заказ может зависнуть до ручного вмешательства.
- **Статус:** Open, учебный дефект. Для подтверждения нужны логи API/RabbitMQ, `order_id` и повторный тест.

## 4. Протокол инспекции

**Протокол:** PR-06-07-002 · **Объект:** архитектура обработки заказа.

| Замечание | Риск | Рекомендация |
|---|---|---|
| Нет гарантии сохранения события при отказе брокера | Заказ зависает | Transactional outbox и повторная публикация |
| Не подтверждена идемпотентность consumer | Повторные побочные эффекты | Обработка по `event_id` / `order_id` |
| Нет сквозной корреляции | Сложно расследовать сбой | Передавать `correlation_id` |
| Не описана обработка неисправимых сообщений | Сообщение блокирует очередь | DLQ и регламент повторной обработки |

## 6. Рекомендации и вывод

1. Сохранять изменение заказа и событие в одной транзакции PostgreSQL через **transactional outbox**.
2. Публиковать события с повторами и контролем ошибок; для неисправимых сообщений использовать DLQ.
3. Сделать обработчики идемпотентными и передавать `correlation_id`.
4. Повторить тест с отключением/восстановлением RabbitMQ и проверить отсутствие потери события и дублирования действий.

**Вывод:** по учебной модели релиз не рекомендуется до устранения BUG-001 и проверки повторной доставки. Фактический статус системы можно определить только после реального прогона.
