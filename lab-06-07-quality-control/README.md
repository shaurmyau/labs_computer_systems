# Семинары 6–7. Документирование результатов контроля качества

## Выбранная система

OrderFlow — та же учебная система обработки онлайн-заказов, что используется в семинаре 5. В рамках этой работы анализируется учебная сборка 1.0.0-rc1.

## Состав результатов

- docs/test-report.md — отчёт о тестировании со статусом релиза, тестовой средой, планом/фактом проверок, дефектами и рисками.
- docs/defect-BUG-001.md — воспроизводимая карточка дефекта с шагами, ожидаемым и фактическим результатом, серьёзностью, приоритетом и видами доказательств.
- docs/recommendation.md — корректирующая рекомендация, ответственный, срок и способ проверки эффективности.
- src/quality_metrics.py — расчёт плотности дефектов, доли пройденных тестов, покрытия требований, эффективности обнаружения дефектов и MTTR.
- tests/test_quality_metrics.py — unit-тесты расчётных функций.

## Запуск расчётов и тестов

Из этого каталога:

~~~bash
python3 src/quality_metrics.py
python3 -m unittest discover -s tests -v
~~~

Внешние библиотеки не требуются.

## Важное ограничение достоверности

В задании допускается самостоятельно определить исходные данные для выбранной реальной или описанной системы. OrderFlow здесь является учебной моделью, а не поставленной в репозиторий реализацией приложения. Поэтому числовой прогон, сборка, дефекты и параметры стенда ниже являются учебным примером для заполнения структуры отчёта. Они не утверждают, что реальные интеграционные тесты выполнялись на доступном стенде. Для реального релизного решения нужно заменить модельные данные результатами тестирования приложения.
