# Описание системы OrderFlow

## Назначение

OrderFlow — учебная информационная система, предоставляющая клиентам каталог товаров, оформление заказов и просмотр состояния ранее созданных заказов. Система включает HTTP API, веб-клиент, реляционную базу данных и фоновые обработчики.

## Целевая аудитория

- Покупатели, создающие и отслеживающие заказы.
- Операторы, обрабатывающие исключения и обращения.
- Администраторы, сопровождающие сервис и анализирующие качество.

## Характер нагрузки

Базовая нагрузка распределена в течение дня. Ожидаемые пики — 12:00–14:00 и 18:00–21:00. Для расчёта SLI используются только пользовательские API-запросы; технические маршруты /health и /metrics не учитываются. Плановые работы должны быть объявлены и отдельно отражены в отчёте SLA.

## Критические бизнес-функции

1. **Получение каталога.** Клиент получает актуальные карточки доступных товаров.
2. **Оформление заказа.** Валидный заказ принимается API, сохраняется и получает идентификатор.
3. **Получение статуса.** Клиент может получить подтверждённый статус своего заказа.

## Границы измерения

SLI измеряются на внешнем HTTP API от момента получения запроса балансировщиком до ответа API, а для сохранности заказа — от подтверждения HTTP-запроса на создание до проверки, что заказ доступен для чтения не позднее 60 секунд.

Измерения выполняются с серверной стороны и проверяются синтетическими пользовательскими запросами. Ошибки клиента 4xx не включаются в знаменатель доступности, поскольку они обычно отражают некорректный запрос пользователя. Серверные 5xx, timeout и недоступность сервиса включаются как неуспешные запросы.
