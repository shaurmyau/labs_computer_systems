# Задание 4. Бюджет ошибок и принятие остаточного риска

## Исходные учебные данные

- SLO доступности API Sirius EDA: 99,95%.
- Период цели: 30 календарных дней; для годового бюджета используются 8760 часов.
- Фактический учтённый простой за отчётный год: 1,25 часа (75 минут).
- Меры: мониторинг, реплика/автоматическое переключение и проверенное резервное копирование.
- Не внедряется: полноценная active-active георезервированная инфраструктура в дополнительном регионе.

## Расчёт бюджета ошибок

~~~text
B% = 100% − SLO
B% = 100% − 99,95% = 0,05%

B = T × (1 − SLO)
B = 8760 × (1 − 0,9995) = 4,38 часа/год
~~~

Фактический простой за период — 1,25 часа.

~~~text
Bостаток = 4,38 − 1,25 = 3,13 часа
Расход бюджета = 1,25 / 4,38 × 100% = 28,54%
~~~

| Показатель | Формула | Значение |
|---|---|---:|
| Целевое SLO | задано | 99,95% |
| Бюджет ошибок в процентах | 100% − SLO | 0,05% |
| Годовой период | T | 8760 ч |
| Бюджет ошибок в часах | 8760 × (1 − 0,9995) | 4,38 ч |
| Учтённый простой | задано | 1,25 ч |
| Остаток бюджета | 4,38 − 1,25 | 3,13 ч |
| Доля расхода | 1,25 / 4,38 × 100% | 28,54% |

Для скользящего месяца в 30 дней соответствующий бюджет простоя равен 720 × 0,0005 = 0,36 часа, то есть 21,6 минуты.

## Политика расходования бюджета

Для учебного примера установлена следующая политика:

- При расходе 50% бюджета — предупреждение владельцу сервиса и анализ burn rate.
- При расходе 80% — ограничение рискованных изменений, обязательная проверка rollback и усиленный контроль релизов.
- При расходе 100% — заморозка плановых изменений, кроме исправлений надёжности и безопасности, до восстановления бюджета по согласованной политике.

Расход 28,54% годового бюджета ниже порога предупреждения 50%, поэтому ограничение изменений по принятой политике пока не требуется. При этом локальные всплески burn rate могут потребовать реакции даже при небольшом годовом расходе.

## Документ о принятии остаточного риска

| Поле | Содержание |
|---|---|
| Риск | Отказ основной зоны размещения одновременно затрагивает API, PostgreSQL и RabbitMQ Sirius EDA; восстановление занимает больше ожидаемого |
| Вероятность | 1% в год (учебная оценка) |
| Последствия | До 250 000 ₽ потерь на инцидент, включая недополученную выручку, обработку накопленных заказов и компенсации |
| Меры снижения | Регулярный backup, проверенные restore-drills, реплика в другой зоне доступности, мониторинг и инструкция восстановления |
| Не внедряемая мера | Полноценный active-active второй регион с автоматической маршрутизацией |
| Причина принятия | Учебная оценка ожидаемых потерь: 0,01 × 250 000 = 2 500 ₽/год; годовая стоимость active-active оценивается в 90 000 ₽, то есть несоразмерна ожидаемому снижению риска |
| Ответственный | Руководитель эксплуатации / владелец сервиса |
| Срок пересмотра | Через 6 месяцев либо после регионального инцидента, роста оборота или изменения требований SLA |

Решение о принятии риска действительно только при сохранении перечисленных компенсирующих мер, проверенном восстановлении из резервной копии и наличии актуального runbook. Если эти меры перестают выполняться, риск нельзя считать осознанно принятым.

## Осознанное принятие риска и игнорирование

Осознанное принятие означает, что риск описан, вероятность и последствия оценены, владелец назначения указан, меры снижения действуют, решение ограничено сроком и пересматривается по заданным событиям. Игнорирование означает отсутствие оценки, ответственного и плана пересмотра; в таком случае организация не знает, какое последствие она фактически принимает.

## Итоговый вывод

В первую очередь следует внедрить мониторинг и оповещение, репликацию с автоматическим переключением в пределах доступной зоны и регулярные проверки резервного восстановления: по учебной модели их чистый ожидаемый эффект положителен. Полноценный active-active второй регион можно принять как остаточный риск только при сохранении компенсирующих мер и контролируемом расходе error budget. Решение нужно пересмотреть при росте вероятности регионального отказа, увеличении стоимости простоя, ужесточении SLA или приближении расхода бюджета к 80%.
